# Clerk 0.5.0 release verification

Both supported fresh Linux server journeys passed against the normal public Godspeed Mission
Control 2.0.0-beta.6 release. The frozen first-install failures are in
[the beta.6 brief](2026-10-24-beta6-first-walkthrough.md). Program changes started only after
that brief was recorded.

## Fresh installations

The Docker server was installed first with the actual public `/server` installer, then stopped.
A different fresh native server was installed with the actual public `/install` installer.
Both public installers and both candidate Clerk README installers returned exit 0. No previous
workspace or application data was imported. The candidate runtime archive's SHA-256 was
`2c81dba06df2a6a5b52c77532951bb5d9ca8abec6da2813ec683a250b8c61e75`; all 61 runtime and installer
files in it matched the release checkout after the journeys.

The public Godspeed release, source revision and immutable image pin are recorded in the frozen
brief. Docker used its actual released container and native used its actual installed source,
services and Hermes runtime. Both normal first setups selected a made-up custom model provider.
An actual request through each released `godspeed-model` reached the local recorded HTTP
provider before Clerk setup. No replacement model command or notebook address was supplied.

Both journeys proved:

- Paperless 3.3.3 installed with the actual notebook profile's `Europe/Berlin` time zone.
- CA-trusted HTTPS with the same leaf certificate as the healthy Godspeed notebook.
- Password-only sign-in refused, followed by password and authenticator sign-in accepted.
- Normal Google app consent, documents folder, folder plan, confirmation and resume.
- A multipart PDF phone scan accepted and read by real Paperless OCR.
- A named, correctly dated copy filed into the confirmed pretend Drive folder.
- A note, collection item and deadline in the actual installed notebook, with the note marked
  to skip further AI processing.
- Actual tools-free model requests and first-scan Telegram delivery through the verified
  assistant's discovered connection, followed by active Clerk status.

Docker's first harness run omitted the README's `godspeed-clerk phone` step. Its upload, filing
and notebook checks passed, but no first-scan announcement was expected without that step. The
harness was corrected, the normal phone command was run, and a second different made-up invoice
passed the complete journey, including Telegram. No program change was made for this correction.
The tracked reviewer helper follows the README order from the beginning.

Safe receipts: [Docker](evidence/clerk-0.5-docker.json) and
[native](evidence/clerk-0.5-native.json). They contain made-up document facts, counts, versions,
test hostnames and certificate fingerprints only.

## Native update

After the fresh journeys, the actual native 0.4 baseline was started separately and updated with
the same README installer. Its old individual import and site existed before the update. The
site moved to `/etc/caddy/godspeed-addons/godspeed-clerk.caddy`, the old import/site were removed,
the supported wildcard remained, and the actual Caddy binary validated the configuration.
Paperless then answered HTTP 401 through CA-trusted HTTPS using the same certificate.

The workspace, pause state, approved AI and existing Paperless URL/account/token were preserved.
Paperless's container identity and start time were unchanged. The installer ended at Clerk
0.5.0. [The safe migration receipt](evidence/clerk-0.5-native-migration.json) records these checks;
secret values and full container inspection output were compared in memory only.

## Reproduce and review

[The independent install runbook](../../test/public/README.md) creates separate fresh review
servers, installs through the actual website paths and runs the candidate tarball through the
README installer. Its helpers supply only made-up outside services and explicit local CA trust.
The older machine-test stand-in notebook is not used. Run Docker first, stop it, then run native.
The default is one independent review round; a second is needed only for a negative verdict.

Full private installer output and login files stay root-only in the disposable servers. Private
receipts and downloaded image caches remain in the existing K-backed test bed. Neither complete
installer logs nor login material belong in public release evidence.

The tests use unchanged Godspeed `.localhost` configuration and explicitly trust its real local
Caddy root. Docker's Clerk front shares the real Godspeed certificate storage, as supported by
[Caddy's storage contract](https://caddyserver.com/docs/automatic-https#storage). No public ACME
issuance or external hosting firewall claim is made. Only one capped server ran at a time;
image-only caches and reclaiming the bed's extraction page cache avoided resource pressure.

The final local fast suite passed: 463 tests, one expected platform skip, no failures. The normal
public release tag is also responsible for free Linux, Windows, macOS and real-Paperless CI.
